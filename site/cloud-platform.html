04 / DevOps and infrastructure

Cloud-native microservices platform

Containerized microservices deployed to Google Kubernetes Engine with Terraform, then migrated to Red Hat OpenShift.

Role
Developer
Stack
Docker, Kubernetes, GKE, OpenShift, Terraform, GitHub Actions
Links
Résumé (Software Application Developer)

The problem

Running services reliably takes more than getting them to start. They need repeatable infrastructure, scaling and automated delivery, and they should keep working when moved to a stricter enterprise environment.

What I built

The full path from a Dockerfile to a running, scaled deployment, on two different platforms.

  • →Dockerfiles for each microservice
  • →Google Kubernetes Engine infrastructure defined with Terraform, with Kubernetes manifests for autoscaling and load balancing
  • →A migration to Red Hat OpenShift using Source-to-Image builds and OpenShift Routes, under enterprise security policies
  • →CI/CD with GitHub Actions and Google Artifact Registry

How it works

The migration was the real test. Moving to OpenShift meant adapting to enterprise security policies and replacing the delivery path with Source-to-Image builds and OpenShift Routes. When pods failed, I debugged them down to the root cause.

Outcome

2

Kubernetes platforms deployed to

The project gave me hands-on experience with the whole path from container to production-style deployment, and with how much the target platform shapes that path.
