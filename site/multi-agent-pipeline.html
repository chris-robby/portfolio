Multi-agent AI pipeline

Specialized AI agents that collaborate through graph-based orchestration, with limits that keep latency and API cost in check.

Role
Developer
Stack
Graph-based orchestration, function calling, schema validation
Links
Résumé (Software Engineer, AI Code Review)

The problem

A single chain of LLM calls is rigid and fragile: one bad output affects everything after it, and an unchecked retry loop can run up latency and API costs.

What I built

A pipeline where specialized agents collaborate dynamically in a graph instead of following a fixed sequence.

  • →Researcher, executor and validator agents, each with a defined job
  • →Function calling so agents can query external tools
  • →Outputs validated against schemas, with self-correction when they fail
  • →Asynchronous execution of tasks that do not depend on each other

How it works

The key decisions were about control. Strict state management keeps the agents consistent with each other, and hard loop limits stop self-correction from turning into runaway latency or API spend.

Outcome

3

specialized agent roles

The project taught me to treat autonomy as something to design limits for. Validation and loop limits are what make an agent system dependable.
