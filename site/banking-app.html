07 / Full stack course project

Banking web application

A banking system built for a software engineering course, with a Java REST API, a React dashboard for each role and a domain model that follows a UML design.

Role
Developer
Stack
Java, Javalin, React, REST APIs, UML
Links
CodeRésumé (Full Stack Developer)

The problem

Banking data leaves little room for error. The API has to reject invalid input, refuse actions a user is not allowed to take and handle failures predictably.

What I built

A complete application built from the course's UML diagram and use cases.

  • →A Java REST API built with Javalin, organized around the use cases: sign-in, accounts, deposits, withdrawals, transfers, card management, audit logs and spending by category
  • →Role-based access for customers, tellers and administrators, enforced by the API itself
  • →A domain model (accounts, savings, cards, checks, transactions, branches) that follows the project's UML diagram
  • →A separate React dashboard for each of the three roles

How it works

Errors are explicit: wrong credentials return 401, a role attempting an action it does not have returns 403, a missing account returns 404, and a rejected transaction returns 400 with the reason. Data is kept in memory behind a single DatabaseManager class, so a real database can replace it in one place.
